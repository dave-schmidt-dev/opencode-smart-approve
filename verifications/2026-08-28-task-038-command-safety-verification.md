**Blind-Spot Discovery.** The compound-safety property here is enforced by model instruction-following, not by code that independently re-derives per-segment safety and cross-checks the model's verdict — this is consistent with the rest of the system's design (INV-3: deterministic policy can force manual but never grant; only the reviewer allows), so it is not a new architectural gap introduced by this task, but it means the live development report's `otherDisagreements: 3` and the general ~1.7% background jitter documented in `SPEC.md:319-328` apply to compound decisions too, and no fixture in this corpus specifically exercises a "one segment safe, one segment reviewer-manual-but-not-deterministic-manual" case repeated enough times to give the compound rule its own disagreement-rate estimate distinct from the single-command baseline — the corpus's ambiguous compounds all pair a safe tail with an already-deterministic-adjacent-strength manual trigger (`--ignored`, `--raw`, `--all --decorate`, `--hidden`, `--no-index`), not a genuinely borderline compound. This is a coverage bound worth recording, not a defect.
